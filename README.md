# AI support agent for @AppleSupport — Hiver SDE Intern take-home

An agent that takes an incoming customer tweet, **classifies** it into one of 8
data-derived intents, **drafts a reply** grounded in how AppleSupport actually
resolved similar threads, and decides **auto-handle vs escalate** with a stated
reason — plus the evaluation that shows how far it can and can't be trusted.
Built on the Kaggle [Customer Support on Twitter](https://www.kaggle.com/datasets/thoughtvector/customer-support-on-twitter)
dataset (Oct–Dec 2017 slice).

**Short version of the result:** the intent classifier is solid (macro-F1
0.60 vs 0.43 / 0.08 for the baselines), the escalation decision is **not
deployable** (it auto-handles 55% of messages that needed a human), and the
reply-quality "win" over a canned "please DM us" is thinner than the pass-rate
suggests. The report is written around *why* — see
[`reports/REPORT.md`](reports/REPORT.md).

## Reproduce the headline in < 15 minutes

The committed headline is **one run: `gemini-3.1-flash-lite` as worker and as
judge, all 233 golden rows**. Every LLM response behind it is committed under
`.llm_cache/gemini/`, so reproducing it needs **no API key and no raw dataset**:

```bash
pip install -r requirements.txt      # Python 3.10+ (developed on 3.13)
make smoke                           # ~30 s  — 14 tests + end-to-end on a mock backend (proves wiring; numbers meaningless)
make eval                            # ~2 min — replays the committed cache -> reports/results.{json,md}
```
Windows without `make`: `.\run.ps1 smoke`, `.\run.ps1 eval`.

`make eval` regenerates `reports/results.json` + `results.md` (the tables in
`REPORT.md` §3) and `reports/agent_golden_preds.jsonl` (the per-row output
behind §4). `data/processed/AppleSupport_*.jsonl` (the BM25 memory + eval pool)
is committed for the same reason; nothing needs the 3M-row `twcs.csv`.

To confirm the cache isn't hiding anything, `git diff --stat` after `make eval`
should show only timestamps/seconds changing in `results.*`.

## Headline (n = 233) — and what it hides

| | agent | simple baseline | trivial baseline |
|---|---|---|---|
| intent macro-F1 / accuracy | **0.60 / 0.67** | keyword 0.43 / 0.42 | majority 0.08 / 0.46 |
| missed-escalation rate ↓ | **0.55** | intent-prior 0.56 | always-escalate 0.00 |
| reply judge pass-rate | **0.91** | retrieval-only 0.64 | canned "DM us" 0.81 |

Full argument in `REPORT.md` §5; the one-paragraph version:

- **Solid:** the LLM classifier beats both baselines; the four largest intents
  are F1 0.70–0.78. Two tiny tone-driven classes (`complaint_churn_risk`,
  `praise_or_non_actionable`, 0.35 / 0.32) drag the macro.
- **Not deployable:** the escalate/auto rule stack auto-handles **55% of
  messages that needed a human** (43 of 78) and is *one row* away from a
  lookup on intent alone. The confidence and retrieval-score floors never fire
  on this data, and the taxonomy routes physical hardware faults (bent phone,
  water damage, logic board) to *auto* by design (`REPORT.md` §4 F1/F2).
- **Thin:** the agent's pass-rate lead over a constant "please DM us" is
  entirely on the *relevance* dimension — groundedness is identical and 88% of
  agent replies are themselves DM redirects, because that is how AppleSupport
  resolved things in-channel in 2017.
- **Labels move the headline:** a human review pass over 139 model-assisted
  rows changed ~9% of labels and, with the model outputs held fixed, moved
  macro-F1 0.63 → 0.60 and missed-escalation 0.53 → 0.55. Single annotator;
  the second decimal is label noise.
- **The judge misses my own trust bar** (κ ≥ 0.6) both when grading its own
  model's output and when a different vendor grades it (§3.4). The pass-rates
  are directional, not precise.

## Design in one paragraph

Intent is a small closed set (8 buckets) derived by clustering ~1,200 inbound
openings and consolidating by hand (`scripts/explore_intents.py`,
`src/intents.py`). The drafter is retrieval-augmented: BM25 pulls the `k=4`
most similar threads from the brand's history *before* a date split, and the
model must ground its reply in how the brand resolved them — it is told not to
invent policy, prices, or account-specific facts. The escalation decision is a
transparent rule stack (hard regex → always-escalate intents → confidence
floor → retrieval-score floor → weak-precedent flag) with an optional LLM
safety veto; **anything uncertain escalates**. Every decision carries a
human-readable `reason` and a `signals` dict so failures can be traced to the
gate that fired (or didn't). Baselines are explicit for all three sub-tasks:
trivial (majority intent / always-auto / canned line) and simple (keyword
labeller / escalate-by-intent-prior / echo the top retrieved precedent).

Things I chose *not* to build, and why, are in `REPORT.md` §1.3 — multi-turn
dialogue, account tools, fine-tuning, embedding retrieval, and Banking77.

## Going beyond the cached run (all optional)

### Re-run live
```bash
export GEMINI_API_KEY="key1,key2,key3"   # comma-separate several keys to pool free-tier quota
make eval-cold                           # deletes .llm_cache/gemini, ~1,150 calls, ~50 min
```
Gemini's free tier is 500 requests/day per key; a full judged run is ~1,150
calls, so `src/llm.py` round-robins across the key list and drops a key for
the rest of the run when it hits a quota error (five keys were pooled for the
committed run). Other OpenAI-compatible backends are one `config.yaml` line
away (`llm.provider`: `groq` / `openai` / `deepseek` / `ollama` / `mock`);
`llm.judge_provider` or `LLM_JUDGE_PROVIDER=…` lets the judge run on a
different vendor than the worker. Reasoning models need `reasoning_effort` set
(already configured) or they truncate the JSON. Gemini model IDs churn — if
`gemini-3.1-flash-lite` disappears, list live ones with
`curl -s https://generativelanguage.googleapis.com/v1beta/models -H "x-goog-api-key: $GEMINI_API_KEY"`.

### Judge-vs-human agreement
```bash
make worksheet                   # -> data/golden/judge_worksheet.csv (36 replies, source hidden; score by hand)
# save your scores as data/golden/judge_human_scores.csv  (mine are committed)
make judge                       # -> reports/judge_agreement.json      (gemini judge, replays cache)
LLM_JUDGE_PROVIDER=groq make judge   # -> reports/judge_agreement_groq.json (cross-vendor; replays .llm_cache/groq)
```

### Rebuild the data from the raw CSV (~5 min)
Only needed to change brand or re-sample the golden set. Put `twcs.csv` from
Kaggle at `Primary Customer Support on Twitter Dataset/twcs/twcs.csv` (or edit
`paths.raw_csv` in `config.yaml`).
```bash
make pick                            # brand ranking -> reports/brand_selection.json (see DECISION_LOG #1 for why Apple)
make prep                            # twcs.csv -> data/processed/<brand>_{history,eval_pool}.jsonl
make candidates                      # stratified sample -> data/golden/golden_candidates.jsonl
python -m eval.label_tool            # interactive labeller -> data/golden/golden_set.jsonl
python -m eval.label_tool --review   # walk the remaining 64 model-assisted rows; flips them to `human`
```
